# 35 - Techniques

Distilled, generalizable knowledge extracted from experience — the "Distill" stage of the CODE workflow. A Technique is not a meeting note or a project summary; it's what generalizes *beyond* the specific situation: a framework, a mental model, a process that worked, a failure mode to avoid.

Create new ones from `90 - Templates/Technique.md`.

**When to create one:** after closing a project phase and reflecting on what generalized; when a "What I Learned" weekly-review bullet deserves a permanent home; when `autoresearch` surfaces a reusable framework.

**Naming convention:** name by the generalizable skill, not the specific project — `Structuring a Multi-Phase Strategy Engagement.md`, not `Project X Lessons.md`.

**Used by:** `note-creation`, `note-update`, `autoresearch` (Step 4, technique extraction), `knowledge-retrieval` (checks here first, before external research). Worth keeping even if lightly used — it's the highest-leverage folder in the whole system once it has a few real entries.
